The Host Seam src/types/host.ts

The entire CLI interacts with the OS strictly through the Host interface. In production, unixHost executes commands, prompts, and filesystem operations. In automated tests, fakeHost mocks everything in memory with zero real mutations.

Configuration Source of Truth dotfiles.json

Single repository configuration file validated by schema/dotfiles.schema.json. Resolves preset tools toggles (ghostty, zed, skills, piPackages, omzPlugins) and customized package lists.

1 dotfiles init — Full Bootstrap Lifecycle
Primary Command
Upfront Questionnaire Architecture: All user prompts (workflow continuation, .env modification, store location selection, and Ghostty installation) are gathered upfront. Once answered, the 14-step live progress session runs completely uninterrupted in one shot.
Phase 1: Entry & Preflight Exit 1 on failure

1. Detects package manager (apt, pacman, dnf, zypper). Unknown PM exits 1 before modifying state.
2. Loads dotfiles.json. Fails closed on syntax errors.
3. Evaluates workflowLooksPresent() for re-run detection.

Phase 2: Upfront Questionnaire All prompts first

Q1: Re-run: Workflow already present. Continue? [y/N] (declining exits 0).
Q2: Env/.env: Reads .env in repo. Displays names (secrets masked). Prompts Do you want to modify it? [y/N] ➔ Override or Append? [o/A] or CSV fallback.
Q3: Store Location: 1) /etc/environment, 2) ~/.zshenv, 3) ~/.profile, 4) Custom. Confirms target.
Q4: Ghostty: Prompts only if missing and unconfigured in tools.ghostty.

Phase 3: One-Shot Pipeline 14 sequential steps

Executes steps 0 through 13 in a live redrawn dashboard. Component toggles in dotfiles.json (tools.zed: false, tools.skills: false, etc.) mark steps skipped (disabled in preset) quietly without error.

Phase 4: Completion & Reboot session.done()

If login shell was changed to zsh, prompts Reboot to apply it? [y/N]. Answering yes runs sudo reboot. Returns clean exit code 0.

2 dotfiles doctor — Health Diagnostics & Audit Engine
Read-Only Audit
Security & Non-Destructive Guarantee: doctor never writes to disk, never runs installations, and never outputs secret API key values. Missing optional tools (Ghostty) are reported as warnings, not failures.
Phase 1: Dispatch & Preset Resolution loadPreset()

1. Validates CLI flags (rejects unknown options).
2. Loads dotfiles.json. If JSON is malformed, aborts with exit code 1 and error message on stderr.
3. Respects preset.tools configuration (e.g. tools.zed: false excludes Zed from required checks).

Phase 2: Workflow Health Assessment assessWorkflow()

Required Checks: zsh, Oh My Zsh, git, stow, mise, npm, bun, pi, herdr, OpenCode, MCP, login shell, and PATH symlink. OMZ plugins, Zed, and Skills are included only when enabled.
Optional Check: Ghostty status (warns if missing; never fails doctor).
Broken Links: Scans for dangling Stow symlinks in $HOME.

Phase 3: Secret Masking & Key Audit host.listApiKeyNames()

Scans /etc/environment, ~/.zshenv, and ~/.profile. For every variable found, records the key name only. Output lists [ok] <NAME>. Secret values are never exposed or printed.

Phase 4: Summary & Exit Status Exit Code Calculation

Prints formatted diagnostic panel. Returns Exit 0 if requiredOk === totalRequired and zero broken Stow links exist. Returns Exit 1 if any required item is missing or dangling links are detected.

3 dotfiles stow — Symlink Delivery & Conflict Engine
Filesystem Delivery
Idempotent Symlink Delivery: Delivers files from home/ into $HOME. Existing correct symlinks are skipped with no-op; stale symlinks are replaced; conflicting regular files are safely timestamp-backed-up.
skip Stale/broken symlink ➔ replace Regular file conflict ➔ backup & link Missing target path ➔ mkdir & symlink POST-LINK OPERATIONS • Relink ~/.local/bin/dotfiles • mirrorMcp() • Generate Stow Report: - linked (destinations) - backed up (stamped) - skipped (existing) • Exit 0
Phase 1: Filter & Scan Tree homeTree()

Recursively scans home/**/*. Excludes junk: .DS_Store, .git, .gitignore, auth.json, and timestamped backup files. Applies Ghostty filters if running via init flags.

Phase 2: Conflict & Backup Handling YYYY-MM-DD_HH:mm:ss

If a real file exists at destination, it is renamed to <file>.YYYY-MM-DD_HH:mm:ss before linking. Re-running on already correct repo symlinks creates zero backups.

Phase 3: PATH Stub Relink ~/.local/bin/dotfiles

Atomically writes and links ~/.local/bin/dotfiles pointing to the repo's bash stub. Guarantees the CLI works from anywhere, even if the user moves the dotfiles repository.

Phase 4: MCP Translate mirrorMcp()

Unless --dry-run is set, reads servers from the Preset mcp key in dotfiles.json and writes translated copies into pi's ~/.pi/agent/mcp.json and OpenCode's mcp key in ~/.config/opencode/opencode.json.

4 dotfiles clean — Timestamp Backup Removal Flow
Safe Pruning
Interactive Safety Guard: Discovers timestamped Stow backups, lists candidate paths, and confirms before removing. Defaults to No ([y/N]).
Delete N backup file(s)? [y/N] • If Yes ➔ host.removeFile() ➔ "Deleted N backup(s)." • If No ➔ "Clean canceled." ➔ Zero files deleted
Phase 1: Regex Pattern Discovery stowBackups()

Scans directories corresponding to homeTree() entries in $HOME. Matches files ending with the strict timestamp pattern: ^\d{4}-\d{2}-\d{2}_\d{2}:\d{2}:\d{2}$.

Phase 2: Empty Check Short-Circuit Zero Backups

If no matching backup files exist, prints No Stow backups found. and exits immediately with code 0 without asking any questions.

Phase 3: Interactive Prompt host.prompt()

Prints each discovered backup path line-by-line so the user sees exactly what will be removed. Asks Delete N Stow backup file(s)? [y/N] with default No.

Phase 4: Removal & Exit host.removeFile()

On confirmation, unlinks each file and prints Deleted N backup file(s).. If declined, prints Clean canceled. and leaves files untouched. Exits 0.

5 dotfiles sync — Atomic Pull & Configuration Sync
Fast-Forward & Re-Stow
Atomic Pull & Fast-Forward Guarantee: Pulls changes fast-forward only. If the repository is dirty or diverged, sync fails fast before modifying anything. Never installs or upgrades tools (ADR 0015).
Phase 1: Dry-Run Mode --dry-run flag

If --dry-run is set: skips git pull completely and evaluates stowTree({ dryRun: true }). Previews linked and skipped files without touching remote origin. Succeeds even on dirty repositories.

Phase 2: Fast-Forward Git Pull host.pullRepo()

Executes git pull --ff-only. If the working directory has unstaged files or untracked conflicts, the pull fails fast. Exits code 1 with an error message. Stows absolutely nothing.

Phase 3: Configuration Re-Stow stowTree()

Links any new configuration files from home/. Conflicting regular files are backed up with timestamps; existing symlinks pointing to the repo are preserved without backup.

Phase 4: MCP Refresh mirrorMcp()

Reads the Preset mcp key in dotfiles.json and refreshes pi's ~/.pi/agent/mcp.json and OpenCode's mcp key in ~/.config/opencode/opencode.json. Prints complete summary and exits 0.
